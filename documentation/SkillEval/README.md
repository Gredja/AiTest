# SkillEval — eval-наборы для генеративных скиллов

Eval-набор — это фиксированный вход + чек-лист «что обязано быть / что запрещено» для одного
скилла. Он превращает правку скилла в проверяемую гипотезу: прогон до → правка → прогон
после → таблица статусов, а не «показалось лучше».

Принцип тот же, что mutation testing vs line coverage: не «есть ли проверка», а «чувствует
ли проверка ошибку» (см. `education/TESTING_PLAYBOOK.md` §14.9).

## Правило (обязательное)

**Любая правка `.mimocode/skills/api-test-gen|e2e-test-gen|ui-test-gen/SKILL.md` → прогон
eval-набора этого скилла перед коммитом.** Гейт в `/commit`: без eval-таблицы в отчете
коммит правки `*test-gen*` блокируется.

## Формат кейса

Один файл на скилл (`api-test-gen.md`, `e2e-test-gen.md`, `ui-test-gen.md`).
Каждый кейс:

- **Вход** — точный запрос, который даётся агенту (service/endpoint + контекст);
- **Обязано** — чек-лист пунктов, которые обязаны присутствовать в ответе (из скилла);
- **Запрещено** — чек-лист того, чего в ответе быть не должно;
- **Статус до / Статус после** — `not run` | `pass` | `fail` (+ дата прогона).

## Как прогонять

1. Зафиксировать версию скилла (git-хэш) в колонке «до».
2. Дать агенту ВХОД кейса, не подсказывая чек-лист.
3. Проверить ответ по чек-листу «Обязано / Запрещено» глазами; JSON-контракт отчёта —
   дополнительно через `powershell -File Scripts/validate-skill-report.ps1 <file>`
   (это единственный механический пункт прогона, остальное — чек-лист).
4. Заполнить статусы, отметить дату и версию скилла.
5. После правки скилла повторить шаги 2–4 в колонке «после»; сравнить таблицы.
