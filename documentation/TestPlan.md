## 5. Test Data Strategy

> **Rule: Non-existent ID tests** — 0 and -1 are safe static IDs (always invalid). For "not found" tests — use dynamic approach: GET all → find maxId → use maxId + 1 (never static 999, may exist as API grows).

| Strategy | Description |
|----------|-------------|
| **Static data** | Use known product IDs (1-20), user IDs (1-10) |
| **Dynamic data** | For non-existent ID tests: GET /products → find max ID → use maxId + 1 |
| **Generated data** | Use Faker or manual random data for POST/PUT |
| **Cleanup** | FakeStoreAPI resets data periodically — no explicit cleanup needed |

## 9. Risks and Mitigations

| Risk | Impact | Mitigation |
|------|--------|------------|
| FakeStoreAPI is unstable/slow | Tests fail intermittently | Add retry logic, timeout = 10s |
| FakeStoreAPI resets data | Tests relying on specific state fail | Use static IDs, independent tests |
| AI generates incorrect tests | False positives | Every AI test reviewed before merge |
| No cleanup after POST/DELETE | Test pollution | FakeStoreAPI resets periodically |
